# 📊 Log Analyzer CLI

Консольная утилита на Python для детального анализа серверных логов.
Поддерживает **Nginx access.log**, **Syslog (sshd)**, **JSON-логи приложений** и **MySQL slow query log**. 
Считает статистику по каждому IP и умеет отдавать отчёт в текстовом виде или JSON.

## 📋 Возможности

- **4 парсера:** nginx, syslog (sshd), json, db (MySQL slow query).
- **Агрегация по IP:** категориальные счётчики (методы, URL, коды, даты,
  пользователи, порты) и числовые метрики (среднее/мин/макс).
- **Гибкая детализация дат:** год → месяц → день → час → минута → секунда
  (`--time`).
- **Два формата вывода:** текстовый отчёт в консоль или JSON в файл.
- **Диагностика:** ошибки парсинга собираются отдельно для каждого IP
  и глобально (нераспознанные строки, битый JSON, некорректный IP).
- **Минимальные зависимости:** только стандартная библиотека.

## 🐍 Требования

- **Python 3.10+** — используются `match/case` и `X | None` в аннотациях.
- Внешних зависимостей нет.

## ⚙️ CLI-опции

| Опция | Обязательная | По умолчанию | Описание |
|---|---|---|---|
| `-f, --file` | да | — | Путь к файлу логов |
| `-t, --type` | да | — | `nginx` \| `syslog` \| `json` \| `db` |
| `--time` | нет | `H` | Детализация даты: `Y` / `m` / `d` / `H` / `M` / `S` |
| `--top` | нет | `10` | Сколько IP показывать в отчёте |
| `--output` | нет | `text` | Формат вывода: `text` \| `json` |
| `-o, --out-file` | нет | `out_file.json` | Путь для записи (только при `--output json`) |

Значения `--time`:

- `Y` — год (`2024`)
- `m` — месяц (`2024-09`)
- `d` — день (`2024-09-19`)
- `H` — час (`2024-09-19 09`) — по умолчанию
- `M` — минута (`2024-09-19 09:45`)
- `S` — секунда (`2024-09-19 09:45:12`)

## 📥 Поддерживаемые форматы

### 1. Nginx access.log (combined / common)

```bash
93.180.71.3 - - [17/May/2015:08:05:32 +0000] "GET /downloads/product_1 HTTP/1.1" 304 0 "-" "Debian APT-HTTP/1.3"
```
**Извлекаемые данные:**

*   IP, дата запроса

*   Дата и время запроса (приводится к выбранному уровню агрегации)

*   HTTP‑метод и URL

*   Код ответа

### 2. Syslog (sshd)
**Распознаются четыре типа событий:**

*   Failed password - неудачная попытка входа

*   Invalid user - попытка входа под несуществующим пользователем

*   Connection closed by - разрыв соединения

*   authentication failure - детальный отчёт об ошибке аутентификации

Остальные строки считаются в `global_errors["syslog"]["unrecognized"]`
и в статистику по IP не попадают.

**Собираемые поля:**

*   Общие: дата, PID процесса, имя пользователя, порт

*   Для authentication failure: дополнительно logname, uid, euid, tty, ruser

### 3. JSON-логи приложений

Каждая строка файла должна быть валидным JSON-объектом с полем ip.
Пример строки:
```bash
{"timestamp": "2026-08-03T10:15:30Z", "service": "auth-service", "level": "INFO", "message": "User login successful", "user_id": 1024, "ip": "203.0.113.5", "duration_ms": 45}
```
**Извлекаемые данные:**
*   Все поля JSON, вложенные структуры уплощаются (flatten) с разделителем _
*   Поля duration_ms и response_time обрабатываются как числовые метрики (среднее, минимум, максимум)
*   Поле timestamp (если есть) - как дата с учётом --time
*   Списки сохраняются как JSON-строки.

### 4. Slow Query логи СУБД
Поддерживается формат MySQL slow query log.
Пример фрагмента:
```bash
# Time: 2026-08-05T10:15:23.456789Z
# User@Host: root[root] @ localhost [127.0.0.1]  Id: 1234
# Query_time: 5.234567  Lock_time: 0.000123  Rows_sent: 10  Rows_examined: 10000
SET timestamp=1754398523;
SELECT * FROM orders WHERE status = 'pending';
```

**Извлекаемые данные:**
*   Тип SQL-операции (SELECT, INSERT, UPDATE, …)
*   Отпечаток запроса (fingerprint) - числа заменяются на ?
*   Числовые метрики: query_time, lock_time, rows_sent, rows_examined
*   Пользователь, хост, ID соединения

## 📄 Структура кода

| Компонент | Назначение |
|---|---|
| `IpStats` | Хранилище статистики по одному IP: `categorical`, `numeric`, `errors`, `total_requests` |
| `GlobalError` | Счётчик глобальных ошибок + ограниченная выборка примеров (`deque` с лимитом) |
| `NginxParser` | Парсер access-логов Nginx |
| `SyslogParser` | Парсер четырёх типов SSH-событий |
| `JsonAppParser` | Парсер JSON-логов с flatten вложенных объектов |
| `DatabaseSlowQueryParser` | Парсер многострочных записей MySQL slow query log |
| `build_report(obj, top_n)` | Превращает `parser.ip_analytics` в plain-dict, сериализуемый в JSON |
| `display(report, values_info)` | Текстовый рендер поверх `build_report` |
| `render_json(report)` | JSON-рендер поверх `build_report` |
| `save_in_file(text, path)` | Запись строки в файл |
| `read_file(...)` | Выбор парсера, чтение файла, запуск парсинга и вывода |
| `is_date / is_match / is_ip` | Вспомогательные валидаторы, пишут ошибки в per-IP или global |
| `main()` | CLI через `argparse` |

Ключевая идея: `build_report` собирает данные один раз, а `display`и `render_json` — **два независимых рендера** поверх одного источника.

Схема потока данных:

```bash
файл лога
    │
    ▼
parser_log(line) ──► IpStats / GlobalError
    │
    ▼
build_report(parser, top_n) ──► plain dict
    │
    ├──► display() ──► текст в консоль
    └──► render_json() ──► save_in_file() ──► .json
```

## ⚠️ Обработка ошибок

Ошибки делятся на два уровня.

**Per-IP** (`IpStats.errors`) — привязаны к конкретному IP:

- `date_parse_failed` — дата не распарсилась или отсутствует;
- `<field>_parse_failed` / `<field>_missing` — поле пустое или отсутствует;
- `<field>_not_number` — числовая метрика не приводится к числу.

**Глобальные** (`parser.global_errors`) — не привязаны к IP:

- `parsing/not_match` — строка не соответствует шаблону;
- `parsing/blank_or_comment` — пустая строка или комментарий (`# …`);
- `not_ip/not_dict` / `not_ip/not_string` / `not_ip/incorrect` — проблемы с IP;
- `json/invalid` — невалидный JSON;
- `syslog/unrecognized` — нераспознанная строка syslog.

Для каждой категории хранится `count` (полное число) и до 5 уникальных
примеров (обрезанных до 200 символов) — этого достаточно для диагностики
без риска раздувания памяти на больших файлах.

## 🔮 Планы по развитию

- Форматы вывода: **CSV**, **Markdown**.
- Потоковые статистики для числовых полей (`p50/p95/p99` вместо
  хранения всех значений).
- Top-K с фиксированной памятью для категориальных счётчиков
  (на очень больших файлах с миллионом уникальных URL).
- Фильтры: `--ip`, `--status`, `--since/--until`.
- Чтение из stdin (`-f -`) и запись в stdout (`-o -`).
- Тесты (`pytest`) на фикстурах для каждого парсера.
